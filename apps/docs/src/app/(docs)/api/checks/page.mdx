# Check a domain

<EndpointHeader method="POST" path="/v1/checks" />

Diagnose any domain, against no account and no profile. **This is the only
endpoint that needs no API key** — it is what the checker on
[propgate.dev](https://propgate.dev) calls, and it is the same engine as
`propgate check` and the sweeper.

It reads DNS and writes nothing. Nothing is registered, no state moves, and
no webhook fires. If what you want is to re-check a domain you have already
registered, that is
[`POST /v1/domains/:id/checks`](/api/domains/verify) instead.

<Callout>
  `propgate check example.com` without `--remote` resolves on the machine it
  runs on rather than calling this endpoint. That is usually the one you want
  when a customer reports something odd: it answers from *their* resolver's
  point of view rather than ours, and the disagreement between the two is
  often the whole diagnosis.
</Callout>

Every finding carries a [diagnosis code](/taxonomy), what was `observed` and
what was `expected`. `lookups` is the derivation: which queries were sent, to
which server, and what each returned. A verdict you cannot audit is a verdict
you have to take on faith.

## Rate limit

**20 checks a minute per address**, keyed on `X-Forwarded-For`. A check costs
up to about twenty upstream queries aimed at whichever authoritative servers
the caller names, so an unauthenticated endpoint is sized against other
people's infrastructure rather than ours.

<CodeBlock code={CHECKS_RATE_LIMITED} lang="http" />

If you are checking domains on a schedule, register them instead and let the
sweeper do it — that is what it is for, and it does not come through here.
