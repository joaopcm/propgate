## Why `lookups` is here and not on the list

Every check carries the queries that produced it: the DNS `name` asked,
`type` (the numeric RR type, e.g. `16` for TXT), which `server` answered
(`address:port`), and `status`. A verdict you cannot audit is a verdict you
have to take on faith, and "why did you say that" is the question a disputed
result produces.

`status` is coarser than it looks: it is `answered | timeout | unreachable |
malformed | truncated`, the transport-level outcome, not the DNS response
code. An `answered` lookup for a name that does not exist, like the
`DKIM_RECORD_MISSING` case above, still reports `status: "answered"`, because
the server answered; it just said NXDOMAIN. Read the finding's `code` for that
distinction, not `status`.

This is the field the [list endpoint](/api/domains/list) omits, at roughly
4.4× the per-domain size. Fetch a domain individually when you need to show
someone why a check came back the way it did.
