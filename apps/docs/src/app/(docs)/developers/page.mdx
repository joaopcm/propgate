# propgate developer portal

API keys, documentation, a public sandbox, and the machine-readable files
agents should start from. This is the propgate developer surface — not a
marketing page.

## Get a key

Two calls, no sales conversation.

1. `POST https://api.propgate.dev/v1/signup` with `{"email":"you@example.com"}`
2. `POST https://api.propgate.dev/v1/signup/confirm` with the six-digit code

The confirm response returns the key once. After that only a hash is stored.
Named keys later are `POST /v1/api-keys`. See [Authentication](/authentication).

## Sandbox

No key required. The same engine as the CLI and the sweeper:

```
curl -s -X POST https://api.propgate.dev/v1/checks \
  -H 'content-type: application/json' \
  -d '{"domain":"github.com"}'
```

Or the checker on [propgate.dev](https://propgate.dev). Rate limited to 20
checks a minute per address. For scheduled checks, register the domain and
let the sweeper do it.

There is no MCP server. Function-call the operations in `/openapi.json`. The
public checker is `checkDomain`. Authenticated work uses the bearer key from
signup.
